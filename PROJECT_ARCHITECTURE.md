# BYE QUIZ LIVE — المرجع المعماري الشامل والتوثيق التقني

تطبيق **BYE QUIZ LIVE** هو منصة ألعاب تفاعلية وبث مباشر إنتاجية متكاملة (Interactive TikTok LIVE Game Show Platform)، مصممة بالكامل وفق معايير البث العمودي 9:16، وتعمل كـ PWA متقدم بدون أي إيموجي يونيكود تقليدي، معتمدة بالكامل على الرسوم المتجهية (SVG) ومحركات المؤثرات السينمائية والإجرائية (Canvas / Web Audio API) وقاعدة بيانات PostgreSQL مع نظام تخزين احتياطي فوري (Resilient In-Memory/JSON Fallback).

## 💾 2. طبقة قاعدة البيانات واستمرارية البيانات (Database & Persistence Layer)

تعتمد المنصة على معمارية هجينة مرنة توفر الاستقرار والموثوقية في بيئات الإنتاج والتطوير:

### 1. قاعدة بيانات PostgreSQL (الخيار الإنتاجي الأساسي)
- يتم تفعيلها تلقائياً عند تمرير المتغير البيئي `DATABASE_URL`.
- تتصل بالخادم عبر مجمع الاتصالات `pg.Pool` (من حزمة `pg`).
- تنفذ استعلامات SQL مجهزة ببارامترات آمنة تمنع ثغرات SQL Injection.
- تحتوي على 16 جدولاً وفهرساً إنتاجياً يشمل:
  - إدارة المستخدمين والصلاحيات (`admin_users`, `sessions`, `banned_users`).
  - سجل المتسابقين والإحصائيات التراكمية (`users`, `participants`).
  - بنك الأسئلة والمجموعات (`questions`, `questionSets`).
  - جلسات البث والجولات (`games`, `rounds`).
  - سجل الإجابات وسرعة الاستجابة (`answers`).
  - سجل النقاط والهدايا والعمليات المالية (`scores`, `gifts`, `gift_events`).
  - سجل رسائل الشات وأحداث اللعبة وسجلات الفائزين (`chat_messages`, `game_events`, `winners`, `settings`).

### 2. نظام التخزين الاحتياطي التلقائي (Resilient In-Memory/JSON Fallback)
- عند غياب `DATABASE_URL` أو تعذر الاتصال بـ PostgreSQL، لا يتوقف النظام بل يتحول تلقائياً إلى نمط `FALLBACK_STORAGE`.
- يعتمد على مجموعات بيانات حية في الذاكرة (`Map` و `Array`) مع حفظ تلقائي للملفات في مجلد `data/`.
- يضمن استمرار البث والألعاب بدون أي انقطاع مع تسجيل كامل للعمليات في السجل (Logger).

## 🎬 4. دورة حياة الجولة ومراحل المشاهد (Round Lifecycle & Scene Flow)

1. **مرحلة الفعاليات والاستعداد (`WAITING`)**:
   - واجهة تفاعلية ترحيبية برادار ضوئي وبطاقات استعراض الفعاليات وجوائز البث في انتظار دخول المشترك الأول.
2. **اللقطة السينمائية للمشترك الأول (`FIRST_JOIN`)**:
   - إطلاق هالة احتفالية ونغمة فوز سينمائية بمجرد انضمام أول متسابق (`!join` أو `تم`) وعرض بطاقة المقعد VIP #1 لمدة 2.2 ثانية.
3. **مرحلة التسجيل وحجز المقاعد (`REGISTRATION / JOIN`)**:
   - شبكة مقاعد المتسابقين الحية (حسب العدد المحدد من لوحة التحكم أو وضع المقاعد المفتوحة).
4. **العد التنازلي واكتمال الجولة (`COUNTDOWN / PARTICIPANTS`)**:
   - عد تنازلي شعاعي وبصري لتنبيه المتسابقين ببدء طرح السؤال.
5. **طرح السؤال وبدء وقت الإجابة (`QUESTION / ANSWERING`)**:
   - عرض السؤال والخيارات الأربعة (أ، ب، ج، د) مع مؤقت دائري SVG تفاعلي واستقبال إجابات الشات وحساب أول الواصلين.
6. **إغلاق الإجابات وعرض النتيجة (`LOCK / RESULTS`)**:
   - تجميد استقبال الإجابات وتحديد الخيار الصحيح بلون الزمرد المشع وتحديد المتأهلين للسحب.
7. **سحب الحظ الذكي (`DRAW / ROULETTE`)**:
   - دوران روليت آلي بين جميع أصحاب الإجابات الصحيحة لاختيار الفائز بعدالة تامة.
8. **تتويج البطل والمؤثرات (`WINNER`)**:
   - منصة تتويج سينمائية مع إطلاق مقذوفات الكانفاس الذهبية واحتساب نقاط الجولة.
9. **منصة الشرف والمتصدرين (`PODIUM / LEADERBOARD`)**:
   - منصة التتويج للمراكز الثلاثة الأولى وقائمة المتصدرين التراكمية.

## 🛡️ 5. معايير الأمان والتحقق (Security & Validation Standards)

- **تطهير المدخلات (XSS Sanitization):** تنظيف كامل لجميع نصوص الشات وأسماء المشتركين قبل حقنها في DOM.
- **تأمين المسارات (Path Traversal Defense):** تدقيق ومطابقة مسارات الملفات الثابتة عبر دالة `isSafePath` لمنع الوصول خارج مجلد `public`.
- **المصادقة والتشفير:** استخدام خوارزمية `PBKDF2` مع Salt عشوائي لتجزئة كلمات المرور وحماية الجلسات برموز Cryptographic Tokens مع مطابقة CSRF.
- **التحكم بالصلاحيات (RBAC):** دعم 3 مستويات صلاحيات (`SUPER_ADMIN`, `ADMIN`, `OPERATOR`) لمنع غير المصرح لهم من تغيير إعدادات البث الحساسة.
- **نظام الأيقونات النظيف (Zero-Emoji):** اعتماد 100% على SVG Vector Graphics لمنع تفاوت مظهر الإيموجي بين أنظمة التشغيل وضمان مظهر احترافي للبث التلفزيوني.
